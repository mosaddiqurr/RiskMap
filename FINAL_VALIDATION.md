## Production deployment evidence

The active architecture is five pages and two API endpoints in Next.js, using a stateless Node standalone server. It requires no database, worker, credentials or persistence volume.

Two independent production processes were started from built standalone artifacts. The frontend used the normal production startup helper, including bundled static/public assets. Both health endpoints returned `status: ok` and `mode: stateless-analysis`.

The approved frontend compilation used `NEXT_PUBLIC_API_BASE_URL=https://api.riskmap.test:3444`. Disposable local TLS proxies exposed the frontend as `https://riskmap.test:3443` and the API at the separate reserved test host. Browser-only host mappings resolved those reserved names; application source and deployment configuration have no dependency on localhost for public operation. The local test certificate was accepted only by the isolated test browser and was removed during cleanup.

Verified in the actual production configuration:

- The frontend sent analysis POSTs to the separate HTTPS API origin.
- CSP permitted the exact configured API origin.
- The API allowed the exact frontend origin, including OPTIONS and validation-error responses.
- An unapproved origin received 403 without an allow-origin header.
- No wildcard or credentialed CORS was enabled; analysis responses were `no-store`.
- Demo analysis returned three potential paths; Best Next Fix/remediation and report navigation worked.
- All six JSON/CSV downloads across desktop, tablet and mobile saved successfully with correct names and contents.
- Print invocation, report contents and valid PDF rendering passed at all three sizes, without browser application errors.
- Owned smoke-test processes and HTTPS proxies were stopped after verification.

The standard production target is Node standalone hosting. Docker is an optional packaging alternative. Earlier container attempts stalled, and the engine version probe remained unresponsive after disk recovery. No container build/startup success is claimed; validate that route on a functioning Docker host before choosing it. Docker is not a blocker for the independently validated Node architecture.
